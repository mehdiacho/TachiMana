TachiMana Desktop

Ratio Spec — resolution-independent layout handoff

Desktop fork of Yōkai (null2264/yokai) · target Compose Multiplatform (JVM desktop). Companion to the prototype TachiMana Desktop.dc.html and skin studies TachiMana Explorations.dc.html.

Implement to this document, not to screenshots. Every number is tagged FIXED density or SCALING width-class; the vertical axis is always an ordered flex stack with a single weighted spacer — never a coordinate table.

§0 · How to read this spec

Every dimension is one of three kinds:

  • (a) Density — fixed. Type size, radius, stroke, icon glyph, elevation, padding, gap, fixed row/bar/chip heights. In dp (sp for text). Compose density handles HiDPI — never multiply by window width.
  • (b) Width-class — scaling. Only the elements in §1.6 track window width, via window size-class breakpoints (not a raw %).
  • (c) Vertical position. Never a top/height % table. Each screen is a Column/Row of fixed/intrinsic blocks with exactly one Modifier.weight(1f) spacer (or a LazyColumn that absorbs slack).

Baseline reference size: 1360 × 840 dp content area (prototype canvas). Production target 1920 × 1080. All ratios computed @1360 unless noted.

§2.18 · App rotation transform — the monitor-arm feature

Whole-app 90° layout rotation for a physically rotated monitor; OS stays landscape.

  • Trigger: rail Rotate item (§2.2) OR global shortcut Ctrl + Alt + R.
  • Compose Desktop: rotate the root content, not the window. Swap constraints to width = windowHeight, height = windowWidth, wrap in Modifier.graphicsLayer { rotationZ = 90f } centered, and remap pointer input (rotate coords −90° so hit-testing matches).
  • Area outside the rotated content is black. State is per-window and remembered across launch (§3.7 toggle).
  • Window-chrome rule (user decision): because TachiMana draws its own custom titlebar §2.1 inside the rotated root, rotation is a free-floating, optional windowed mode — the whole app incl. titlebar spins, window keeps its bounds. If a platform forces a native non-rotatable OS titlebar, rotation must force borderless/fullscreen (drop native chrome) so no un-rotated bar strands at top. Detect chrome capability at runtime; prefer the custom-titlebar path so windowed rotation stays available.
